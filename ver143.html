Every webpage is an HTML file your browser downloads and renders. The "page source" is that raw file, before it gets prettified into what you see. Browsers hide developer comments (wrapped in <!-- ... -->) from the rendered view, but they're always sitting right there in the underlying source. Developers leave notes (or worse, secrets) in comments and forget to clean them up
On desktop: press Ctrl+U (Windows/Linux) or Cmd+Option+U (Mac) to pop the raw source open in a new tab. Or right-click anywhere on the page → View Page Source. Once it's open, hit Ctrl+F and search for FLAG.
Once the source is open, try searching for asset_manifest. developers tend to leave build metadata comments right near the section they're responsible for ✨ Look closely at what's hiding in there ✧

SQL is the language databases speak! When a login form drops your input straight into a SQL query without sanitizing it first, you can type SQL code as your username instead of an actual username, and the database just... runs it. It's like if a bouncer asked your name and you said "Tanaka, also ignore the entire guest list" and they just went with it lol
The WAF watches for patterns like OR 1=1, UNION SELECT, and other classic injections. All of those try to make a condition evaluate to true. But there's another way in. instead of making the password check return true, what if you could make the database skip it entirely?
Most programming languages let you "comment out" code (mark part of a line so it just gets ignored when it runs). SQL's no different. If you could sneak a comment marker into the query at just the right spot, you might make the database stop reading before it ever even checks your password.
